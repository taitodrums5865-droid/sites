What Is a Batch API and Why Does It Cost Less?

A batch API takes many requests at once and processes them asynchronously within a time window, usually 24 hours, at half the standard token price. You don't get an answer for each call right away. You send a file or list of requests, the provider runs them when it has spare capacity, and you collect the results later.

Each provider states the trade in its docs. OpenAI says the Batch API offers a "50% cost discount compared to synchronous APIs" and that each batch "completes within 24 hours (and often more quickly)" (OpenAI Batch guide). Anthropic says the Message Batches API reduces costs by 50% and that most batches finish in under an hour (Anthropic batch processing). Google prices batch usage "at 50% of the standard interactive API cost" with a 24-hour target (Gemini Batch API).

The discount exists because you let the provider choose when to run your work. Interactive traffic has peaks and quiet periods, and batch jobs can fill the quiet periods. There is a second benefit: batch traffic has its own rate limits. OpenAI describes a separate pool with "substantially higher capacity" than the standard endpoints (OpenAI Batch guide), so a large batch job won't use up the limits your live product depends on.

Conditions (Create a Message Batch reference, batch processing guide):

  • One batch can hold up to 100,000 requests or 256 MB, whichever limit you hit first. Going over the size limit returns a 413 request_too_large error.

How to Submit a Batch Job on OpenAI, Claude, and Gemini

Every batch job follows the same pattern: build the requests, submit them, poll the status, and download the results matched by ID. OpenAI requires a JSONL file. Claude takes the requests directly in the API call. Gemini accepts either.

OpenAI (Python SDK)

Based on the OpenAI Batch guide:

  1. Write batch_input.jsonl with one request per line. Example line:

{"custom_id": "ticket-0001", "method": "POST", "url": "/v1/chat/completions", "body": {"model": "gpt-5-mini", "messages": [{"role": "user", "content": "Summarize: ..."}]}}

  1. Upload it with client.files.create(file=open("batch_input.jsonl","rb"), purpose="batch").
  2. Create the batch with client.batches.create(input_file_id=file.id, endpoint="/v1/chat/completions", completion_window="24h").
  3. Poll client.batches.retrieve(batch.id). The status moves through validating → in_progress → finalizing → completed. It can also end as failed, expired or cancelled.
  4. Download client.files.content(batch.output_file_id). Also check error_file_id, which holds the failed lines.

Common mistake: the url in each line doesn't match the endpoint you passed to batches.create. Use the same endpoint everywhere.

Claude (Python SDK)

Based on Anthropic's batch processing guide and the API reference:

  1. Build a list of requests. Example: {"custom_id": "ticket-0001", "params": {"model": "claude-sonnet-5-5", "max_tokens": 1024, "messages": [{"role": "user", "content": "Summarize: ..."}]}}. Treat the model string as an example and copy the exact ID from the models page.
  2. Submit with client.messages.batches.create(requests=[...]), which calls POST /v1/messages/batches.
  3. Poll client.messages.batches.retrieve(batch_id) until processing_status is ended.
  4. Loop over client.messages.batches.results(batch_id) and check each result.type.

Common mistake: a duplicate custom_id. IDs must be unique within a batch, so generate them from your database primary key.

Gemini (google-genai Python SDK)

Based on the Gemini Batch API docs:

  1. For small jobs (under 20MB), pass a list of GenerateContentRequest objects inline. For larger jobs, write a JSONL file where each line has a key and a request, for example {"key": "ticket-0001", "request": {"contents": [{"parts": [{"text": "Summarize: ..."}]}]}}.
  2. Upload the file with client.files.upload(...), setting the MIME type to jsonl.
  3. Create the job with client.batches.create(model="gemini-2.5-flash", src=uploaded_file.name, config={"display_name": "nightly-tickets"}).
  4. Poll client.batches.get(name=job.name). Job states are pending, running, succeeded, failed, cancelled and expired.
  5. When the job succeeds, download the result file, or read the inline responses if you sent the requests inline.

Common mistake: assuming results come back in input order. Join on key.

What Are the Token and File Size Limits for Batch Requests?

A single batch can hold 50,000 requests or 200 MB on OpenAI, 100,000 requests or 256 MB on Claude, and a 2GB input file on Gemini. Separate token-queue limits also cap how much work you can have waiting at one time.

These limits decide how you split a job. As an example, take 120,000 ticket summaries. On OpenAI that's at least three batches (50,000 + 50,000 + 20,000). On Claude it's two. On Gemini it could be one file if the total fits under 2GB and your tier's enqueued-token limit.

Watch the queued-token limit more closely than the request count. A batch that fits the 200 MB or 256 MB size limit can still be refused if its total prompt tokens push your queue over the per-model limit. If that happens, submit chunks in sequence and start the next one when the previous one completes.

Large documents bring their own problem. Each request inside a batch still has to fit the model's context window and output limits. Batching changes how requests are scheduled and billed. It doesn't change how much one request can contain.

When Should You Use Batch API Instead of Real-Time API?

Use the batch API when nobody is waiting for the answer and the work can wait up to a day. Good fits are evaluations, data labeling, bulk summarization, embedding backfills and nightly reports. Anthropic lists large-scale evaluations, content moderation, data analysis and bulk content generation as typical uses (Anthropic batch processing).

A quick test: if the result goes to a person or system that can wait until tomorrow morning, batch it. If it goes to a user who is looking at a loading spinner, don't.

Workloads that usually suit batch, with examples:

  • Running a regression eval of 5,000 prompts before each model upgrade.
  • Classifying last month's support tickets by topic for a dashboard.
  • Generating product descriptions for a catalog import.
  • Re-embedding a document store after you switch embedding models (OpenAI supports /v1/embeddings in batch).

Workloads that don't suit batch:

  • Chatbots, copilots and anything a user waits on.
  • Multi-step agents whose next call depends on the last result. Each round trip could take hours.
  • Jobs with a hard deadline shorter than 24 hours. "Most finish in under an hour" on Claude describes typical behavior, not a guarantee.

Pitfall: treating batch as faster bulk processing for a deadline. Fix: if a 9 a.m. report needs data, submit the batch the previous afternoon so a full 24-hour run still finishes in time. On Gemini, plan around the 24-hour target and keep in mind that jobs only expire at 48 hours.

A predictable bill comes from moving whole categories of work to batch, not individual calls. List your monthly token spend by feature, mark each feature as interactive or deferrable, and batch the largest deferrable one first.

Can You Combine Batch Discounts with Prompt Caching?

Yes on Claude, where the batch discount and prompt caching stack. OpenAI lists a separate batch cached-input price. On Gemini, a cache hit inside a batch is billed at standard context caching rates instead of getting a further batch discount.

Claude: discounts stack, but cache hits are best-effort

Anthropic's docs say the batch and prompt caching discounts can be combined (Anthropic batch processing). At standard rates on Claude Sonnet 5.5, cache reads cost $0.10 per MTok against $2 for base input (Claude pricing). Requests in a batch run concurrently, though, so cache hits are best-effort. Don't put an assumed hit rate in your budget.

Two practical rules:

  1. Put the shared content (system prompt, rubric, reference document) first and make it identical byte for byte across every request. Use the same cache_control block in each request.
  2. Batches can run longer than the default 5-minute cache lifetime, so consider the 1-hour cache duration. A 1-hour cache write costs 2x base input versus 1.25x for the 5-minute write (Claude pricing page), so it only pays off when many requests share the prefix.

Example: an eval with a 10,000-token rubric shared by 5,000 requests. Without caching, the rubric alone is 50M input tokens, which costs $50 at Sonnet 5.5's $1 batch input rate. Every cache hit on the rubric is billed at the cache-read rate, which is far lower. Plan for the uncached cost and count any cache hits as extra savings.

OpenAI: cached input has a batch price

The OpenAI pricing page lists a batch cached-input rate for GPT-5-family models, for example $0.0625 per 1M tokens for gpt-5 compared with $0.125 at standard rates (OpenAI pricing). OpenAI's caching applies to repeated prompt prefixes automatically, so the prompt-ordering rule from the Claude section applies here too. GPT-4.1 models show no batch cached-input price on that page.

Gemini: caching and batch are billed separately

Gemini batches support context caching. You reference a cached_content resource in individual requests, and when a request hits the cache, you pay the standard context caching rates (Gemini Batch API). Implicit caching is on by default for Gemini 2.5 and newer models, with no storage fee. Explicit caches add an hourly storage charge, for example $0.50 per 1M tokens per hour for Gemini 3.8 Flash (Gemini pricing; Gemini optimization guide).

Pitfall: keeping an explicit cache alive through a long batch queue. Storage is billed hourly while the job waits, so for small shared prefixes, batch pricing without an explicit cache may cost less.

Next steps

Start with one deferrable job that already costs you money and move it to batch this week.

DIY actions for today:

  1. Export last month's usage from your provider dashboard and mark each feature as "user waits" or "can wait 24h." Your first batch candidate is the largest "can wait" item.
  2. Turn 100 real requests from that feature into a test batch, using the commands in the submit section above. Compare the output with your live results and check how long it took.
  3. Add custom_id (or key) joins and an error-file check to your pipeline before you scale the job up.

If you'd rather not build it yourself: Google Cloud's Vertex AI and Amazon Bedrock both offer managed batch inference inside their cloud consoles, with billing, IAM and storage handled by the cloud account. Costs follow each platform's model pricing page (as of October 2026; check the official pages), plus storage fees. This suits teams that already run on GCP or AWS and want procurement, logging and access control in one place. It doesn't suit a two-person startup with no cloud setup, because configuring buckets and permissions is extra work, and model availability and prices can differ from the direct APIs. If you spend heavily, the OpenAI, Anthropic and Google sales teams can also discuss committed-use terms. Ask them directly. Don't assume a discount exists.

FAQ

What is the Claude batch API discount?

The Claude Message Batches API charges 50% less for input and output tokens on every current model. On Claude Sonnet 5.5, that's $1 input and $5 output per million tokens instead of $2 and $10 (as of October 2026). Most batches finish in under an hour, and the maximum is 24 hours (Anthropic docs).

What is the OpenAI batch API discount?

OpenAI gives 50% off compared with synchronous APIs, covering input, output and cached input tokens. Each batch completes within 24 hours, and "24h" is the only completion window available. One batch can hold up to 50,000 requests or a 200 MB file (OpenAI Batch guide).

Is the Anthropic batch API discount combined with prompt caching?

Yes. Anthropic says the batch discount and prompt caching discounts can be combined. Because batch requests run concurrently, cache hits are best-effort, so plan your budget on uncached batch prices. For long batches, consider the 1-hour cache duration (Anthropic docs).

What is the Gemini batch API discount?

Google prices Gemini Batch API usage at 50% of the standard interactive cost, with a 24-hour target turnaround. For example, Gemini 2.5 Flash drops from $0.30/$2.50 to $0.15/$1.25 per million input/output tokens (as of October 2026). Requests that hit a context cache are billed at standard caching rates (Gemini Batch API, pricing).
