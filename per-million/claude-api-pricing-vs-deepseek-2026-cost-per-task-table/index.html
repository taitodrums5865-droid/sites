DeepSeek V4 API Pricing vs Claude: What Changed in 2026

In 2026, DeepSeek moved to V4 with a 1M-token context and peak/off-peak pricing. Anthropic launched Sonnet 5.5 and Haiku 5.5, and Haiku got a two-tier price split at 100K tokens.

DeepSeek's changes

  • V4 launch (April 24, 2026). DeepSeek released V4-Pro (1.6T total / 49B active parameters) and V4-Flash (284B / 13B active). Both have a 1M-token context and both thinking and non-thinking modes. The announcement also says the API works with both OpenAI ChatCompletions and Anthropic API formats.
  • Legacy model retirement. deepseek-chat and deepseek-reasoner were retired after July 24, 2026, 15:59 UTC. If you still have those names in old code, update them.
  • Peak and off-peak pricing. According to the pricing page, peak hours are 01:00–04:00 and 06:00–10:00 UTC, Monday to Friday, not counting Chinese public holidays. Off-peak rates are half of peak. That means US business hours (roughly 14:00–22:00 UTC) and all weekend traffic are billed at the off-peak rate.
  • Current model IDs. deepseek-flash points to DeepSeek-V4.1-Flash-1017 and deepseek-v4-pro points to DeepSeek-V4-Pro-0813. Both allow up to 384K output tokens. The concurrency limits are 2,500 requests for Flash and 500 for Pro (pricing page).

Anthropic's changes

  • Sonnet 5.5 came out on September 28, 2026 at $2/$10. Cache reads cost $0.10, which is 5% of base input. Older Claude models charge the standard 10%.
  • Haiku 5.5 came out on October 7, 2026 with the 100K-token price split shown above.
  • Tokenizer. Haiku 5.5 uses the tokenizer introduced with Claude Opus 4.7. The same text comes out to about 30% more tokens than on Haiku 4.5. A lower per-token price doesn't fully carry over into a lower bill, so compare cost per task, not cost per token.
  • Context. Every current Claude model has a 1M-token context and 128K max output. On the Batch API you can get up to 300K output tokens with the output-300k-2026-03-24 beta header (models overview).

What Do API Pricing Models Actually Mean?

An API pricing model is a set of per-million-token rates, split into input and output. Modifiers such as cache writes, cache reads, batch discounts and time-of-day discounts change the price you actually pay.

Here are the terms you'll see on both vendors' pages:

To estimate the cost of one request:

  1. Count the tokens that are the same on every call (system prompt, tool definitions, reference docs). These are your cacheable tokens.
  2. Count the tokens that change on every call (the user message, retrieved snippets). These are always billed at base input.
  3. Estimate output tokens, including thinking. If you're not sure, run 20 real requests and read output_tokens from the usage object.
  4. Pick a cache hit rate. Use 0% for one-off prompts and 80–95% for steady traffic that reuses the same prefix.
  5. Cost = cached tokens × (hit rate × read price + miss rate × write price) + changing tokens × input price + output tokens × output price.

For example, take a Sonnet 5.5 request with 20,000 cached tokens, 500 new tokens and 400 output tokens. On a cache hit it costs $0.002 + $0.001 + $0.004 = $0.007. On a miss that writes the cache it costs $0.05 + $0.001 + $0.004 = $0.055. If you want this as a script, the LLM cost calculator in Python guide builds one in five steps.

How Claude's Prompt Caching and Batch Discounts Change the Math

Prompt caching makes repeated input up to 95% cheaper on Sonnet and Opus 5.5 (90% on Haiku). The Batch API takes 50% off everything, and the two discounts stack. Most comparison posts leave both out.

The official numbers

  • A cache read costs 0.05x base input on Opus 5.5 and Sonnet 5.5, 0.025x on Fable 5.1 and Mythos 5.1, and 0.1x on other models.
  • A cache write costs 1.25x base input with the default 5-minute TTL and 2x with the 1-hour TTL.
  • On every 5.x model, prompts shorter than 512 tokens aren't cached, and no error is returned. Older models need 1,024–4,096 tokens.
  • You can set up to 4 cache breakpoints per request.
  • Batch requests are billed at 50% of standard prices, and most batches finish in less than 1 hour. Caching and Batch discounts stack, but cache hits inside a batch are best-effort. Anthropic's docs give typical hit rates of 30% to 98%.

Break-even rule for the cache TTL

With a 5-minute TTL on Sonnet 5.5, the write premium is 0.25x and each hit saves 0.95x, so one hit covers the cost of the write. With the 1-hour TTL the premium is 1.0x, so you need two hits within the hour. Use 1h only when requests on the same prefix are more than 5 minutes apart but come at least twice an hour. The prompt caching cost guide walks through the full formula.

Steps to turn both on

  1. In your Messages API call, add the top-level parameter cache_control: {"type": "ephemeral"}. This is automatic caching. It puts the breakpoint on the last cacheable block and moves it forward as the conversation grows.
  2. For more control, put "cache_control": {"type": "ephemeral"} on the last system block that never changes. Use {"type": "ephemeral", "ttl": "1h"} for traffic that arrives slowly.
  3. Put everything that's identical at the top (tools, system prompt, reference docs) and per-user content at the bottom. Any change above the breakpoint causes a cache miss.
  4. Send a few requests, then check the usage fields: cache_creation_input_tokens, cache_read_input_tokens and input_tokens. If cache_read_input_tokens is 0 on the second identical request, the prefix is changing or it's under 512 tokens.
  5. Move non-urgent work to the Message Batches API. Put the same cache_control blocks in every request of the batch, and use the 1-hour TTL because batches can run longer than 5 minutes (batch docs).

Common mistakes and fixes:

  • A timestamp at the top of the system prompt. It makes every request a miss. Move it below the breakpoint.
  • Reordering tool definitions between requests. This also breaks the cache. Serialize tools in a fixed order.
  • Expecting full cache hits in a batch. Hits are best-effort, so budget for misses. The batch API discount comparison shows how other providers handle this.

The limitation: none of this helps a workload where every prompt is unique and needs an answer in seconds. For that kind of traffic, DeepSeek's base rates win.

Tradier API Pricing: Is It Comparable to LLM APIs?

No. Tradier is a brokerage with a trading and market-data API, and it has nothing to do with Claude or DeepSeek token pricing. It shows up only because "API pricing" autocompletes to it.

According to Tradier's pricing page, plans are Lite ($0/month), Pro ($10/month) and Pro Plus ($35/month), and all three include API access. Charges are per trade and per contract, for example up to $0.35 per options contract on Lite. You don't pay per token. If you're building an AI trading assistant, you'd pay both: Tradier for orders and data, and an LLM API for the reasoning. Budget them as separate line items (as of October 2026; check the official page).

What Developers on Reddit Say About Real Gemini/Claude/DeepSeek Costs

Developer threads on r/ClaudeAI and r/LocalLLaMA are where people post their real bills. The numbers are self-reported and go out of date quickly, so this guide doesn't quote a "typical overrun" percentage. What you can check is why real bills end up above the rate card, and each cause has an official explanation:

  • Tokenizer drift. The same text produces about 30% more tokens on Haiku 5.5 than on Haiku 4.5. DeepSeek uses its own tokenizer too. A per-token comparison of the same text across vendors is only an approximation.
  • Thinking tokens. Sonnet 5.5 runs at high effort by default, and thinking is the default mode on DeepSeek Flash (DeepSeek pricing). Both are billed as output, the most expensive line.
  • Caching quietly not working. Claude skips caching below 512 tokens without an error. DeepSeek's cache is "best-effort" and cleared "within a few hours to a few days" once it's unused, so a 95% hit rate isn't guaranteed.
  • Peak-hour traffic. If your users are mostly in Europe in the morning (06:00–10:00 UTC), much of your DeepSeek traffic is billed at the peak rate.
  • Retries. A failed or timed-out call that you resend means paying for the input twice.

For example, if you plan Task A with Flash off-peak at $52 but half your traffic falls in peak hours and only 50% of requests hit the cache, the real figure lands nearer $277. That's more than 5x the plan, and Haiku 5.5 at a 50% hit rate would cost $160. Plan with pessimistic hit rates.

Next steps

Start with one model on one workload, measure it, and switch only if the measured cost per task justifies it.

DIY, today:

  1. Take 50 real requests from your logs and record input, output and repeated-prefix tokens for each. Put them into the five-step formula above using Haiku 5.5, Sonnet 5.5, deepseek-flash and deepseek-v4-pro.
  2. Add cache_control: {"type": "ephemeral"} to your Claude calls and check cache_read_input_tokens on the second request. On DeepSeek, check prompt_cache_hit_tokens and prompt_cache_miss_tokens instead.
  3. Move one non-urgent job, such as nightly evals or bulk tagging, to the Claude Message Batches API or to a DeepSeek off-peak window, and compare the invoice line a week later.

If you'd rather not manage API costs yourself: for interactive coding and writing, a flat subscription can replace API spend. Claude Pro costs $20/month ($17 billed annually), Max starts at $100/month, and Team costs $20–$125 per seat (claude.com/pricing, as of October 2026; check the official page). This suits individuals and small teams who use Claude interactively and want a fixed monthly bill. It doesn't suit you if you're serving end users from your product, because subscriptions don't replace API access for production traffic. Before choosing, see where the two cross over in Claude API pricing vs Max plan.

FAQ

What does API pricing actually mean for a startup budget?

You pay separately for every million tokens you send (input) and receive (output), and output usually costs 3–5x more. Caching, batch and off-peak discounts lower those rates, but only on traffic that fits their rules. To budget, multiply your expected monthly requests by a per-request cost worked out with a pessimistic cache hit rate.

Is Claude API pricing cheaper than DeepSeek for coding tasks?

It is only cheaper if you use the Batch API. In the example above, Sonnet 5.5 on Batch costs $35 per 1,000 tasks, against $33 for V4-Pro at peak and $16.50 off-peak. For live, interactive coding, DeepSeek V4-Pro costs about half to a quarter of Sonnet 5.5's price, so test quality on your own repo before deciding.

Does DeepSeek V4 beat Claude's cached pricing on long-context RAG?

On price, it does. With reused 150K-token documents and 95% cache hits, V4-Pro costs $10.70–$21.50 per 1,000 queries and Flash costs $2.30–$4.60, against $45 for Sonnet 5.5. DeepSeek's cache is best-effort and gets cleared after hours to days of inactivity, so real hit rates may come in lower.

How does Gemini's official 2026 pricing compare on ai.google.dev?

Gemini 3.8 Flash costs $0.75/$3.75 per million tokens until Dec 31, 2026, and Gemini 4 Argon costs $2/$10 until Nov 30, 2026. After those dates both prices double. That puts Gemini above DeepSeek and at or below Claude Sonnet for now. Context caching on Gemini also charges hourly storage.

What are developers actually paying, according to Reddit threads on Gemini API pricing?

The figures in those threads are self-reported and go out of date within months, so treat them as anecdotes, not benchmarks. The causes behind most high bills are documented and fixable: thinking tokens, cache misses, peak-hour traffic and tokenizer differences. Check your own usage fields rather than relying on someone else's invoice.
