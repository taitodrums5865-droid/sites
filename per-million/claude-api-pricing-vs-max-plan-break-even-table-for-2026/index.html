Claude API vs Max Plan: What's the Core Difference?

The Claude API charges per million tokens you send and receive. Max and Ultra charge a flat monthly fee for capped use of Claude's own apps and Claude Code. Neither replaces the other, because they pay for different products.

The practical difference is predictability. A subscription bill is the same every month, but your work can stop partway through a session or week. An API bill grows with traffic, and it only stops at limits you choose. To compare the two, convert the subscription price into the number of tokens it would buy on the API.

How the Max and Ultra usage limits work

Limits are "shared across Claude and Claude Code," so chat and coding draw from the same allowance (Claude Code with Pro, Max or Ultra). How the plans differ:

  • Max: 5x Pro's usage in each 5-hour window, plus a separate weekly limit, also at 5x Pro (Max plan article).
  • Ultra: Verified accounts have no 5-hour limit, and the weekly limit is 10x Pro. Verification happens automatically, based on account and payment history. Unverified accounts keep a temporary 5-hour limit. If Settings > Usage shows no "Current session" bar, your account is verified (Ultra plan article).
  • Fable models: On Max, Ultra and Team Premium seats, you can spend up to 50% of your weekly limit on Fable, and Fable uses up the limit faster than other models. On Pro, Fable runs only on pay-as-you-go usage credits (Fable on your plan).

Anthropic doesn't publish token counts for these limits. It also says it may add other caps and doesn't guarantee uninterrupted service (Max plan article). You can't read a token quota off the pricing page, so you have to estimate what your usage would cost at API rates.

When you reach a limit, go to Settings > Usage, click Enable under usage credits, and then use Add funds. This usage is prepaid and billed at standard API rates. Use Adjust limit to set a monthly cap (usage credits article).

How to claim the API credits

These steps follow Anthropic's docs:

  1. Make sure you've been on Max or Ultra for at least 7 days. You can claim even if you subscribed through iOS or Android, but the claim itself is done in a web browser.
  2. Check your roles. You need to be the plan's subscriber, and you need the Owner, Admin or Billing role in the Console organization.
  3. On claude.ai, go to Settings > Billing. In the API credits section, select the Console organization that should receive the credits, and link it to accept the program terms.
  4. In the Console, open Billing (platform.claude.com/settings/billing). The credits appear under Promotional credits with their expiry date.
  5. Create an API key and make your first request. You don't have to add a payment method.

Credits arrive each billing cycle, shortly after your plan payment goes through. They expire at the end of the cycle and don't roll over. They cover the Claude API, Managed Agents, the Agent SDK and the Playground. They don't cover Claude Code, extra usage in the Claude apps, or Claude on AWS, Bedrock, Google Cloud or Microsoft Foundry. If you upgrade from Max to Ultra, you get prorated credits right away.

Three details affect any estimate:

  • Long Haiku prompts cost 5x more. Above 100K input tokens, Haiku 5.5 moves to the higher price row. If your app sends large documents, price that tier separately.
  • Cache reads are cheaper on the newest models. Cache hits cost 0.1x base input on most models, 0.05x on Opus 5.5 and Sonnet 5.5, and 0.025x on Fable 5.1 (prompt caching docs).
  • The tokenizer changed. Claude 4.7 and later models produce "approximately 30 percent more tokens" for the same text than earlier models (token counting docs). If your forecast uses token counts from an older model, recount.

The Message Batches API costs 50% less for requests that don't need an immediate answer.

How to Calculate the Break-Even Token Volume Between API and Max

To find the break-even point, divide the plan price by your blended cost per million tokens. Below that volume, the API is cheaper. Above it, the subscription is cheaper, as long as your work fits inside the plan's limits.

The formula

blended $/MTok = (input share × input price) + (output share × output price)
break-even MTok/month = plan price ÷ blended $/MTok

Steps:

  1. Pick the model you use most, for example Sonnet 5.5.
  2. Find your input/output split. If you have no data yet, start with 80% input and 20% output. This is our assumption, not an Anthropic figure. Agentic coding usually leans further toward input, because the same context is re-sent on every turn.
  3. Calculate the blended price. For Sonnet 5.5: 0.8 × $2 + 0.2 × $10 = $3.60/MTok.
  4. Divide the plan price by it. For Max: $100 ÷ $3.60 = 27.8M tokens/month.
  5. Compare the result with your measured or forecast monthly tokens. The estimating section below shows how to get that number.

How the API credits change the break-even

Each plan's price comes back to you as API credits. Say you'd spend at least $100 a month on the Claude API anyway, for a side project, an internal tool or Agent SDK scripts. Then Max's chat and Claude Code access costs you nothing extra.

The decision splits into two cases:

  • Your API spend is under $100/month and you don't need Max's limits: stay on pay-as-you-go. Unused credits expire.
  • Your API spend is ≥$100/month and you also use Claude interactively: Max is usually the cheaper bundle. If you spend ≥$200 on the API and the 5-hour window blocks you, compare Max with Ultra.

Claude API vs Max Plan: Which Is Better for Developers?

To build an app, use the API. Subscription limits apply to Claude's own apps and Claude Code, not to your product's users. A subscription still makes sense for you as a developer, and its credits can pay part of your product's API bill.

A practical setup for a solo developer or a small startup:

  • Your own coding and research: Pro, Max or Ultra, depending on how often you hit limits.
  • Your product's traffic: API keys in a dedicated Console workspace with its own spend limit. Every key and workspace in the linked organization draws from the same credit balance, so per-workspace limits are what keep one project from using up the rest (credits docs).
  • Connecting the two: Link your product's Console organization to the plan so the monthly credits are spent first.

Pitfalls for developers

  • Linking the wrong organization. Each plan links to one Console organization, and "you can't change the linked organization yourself." Fix: link the organization where your product runs. If you linked the wrong one, contact support.
  • Running production on credits with no fallback. If the organization has no other credits, "API requests stop until your next monthly API credits arrive." Fix: keep a small purchased balance, or turn on auto-reload on the Billing page.
  • Building on the Agent SDK's subscription access. When you're signed in with your plan, the Agent SDK and claude -p still draw from your subscription limits. That's because Anthropic paused a planned change, as noted on June 15, 2026. Since October 7, 2026, if you run them with an API key from your linked organization, they use the credits instead (Agent SDK article). Treat subscription access as a personal convenience. This policy has changed before.
  • Pro and Enterprise don't get credits. Only Max, Ultra and Team plans are eligible (credits docs).

How to Estimate Your Monthly Token Usage Before Choosing a Plan

Multiply requests per month by the average input and output tokens per request. Adjust for the share of input that's cached, then multiply by the model's prices. Take the averages from your logs or from a pilot of one to two weeks.

Steps using Anthropic's own tools

  1. Count a typical prompt. Call the token counting endpoint (POST /v1/messages/count_tokens) with your real system prompt, tools and a sample user message. In Python: client.messages.count_tokens(model="claude-sonnet-5-5", system=..., messages=[...]). It returns {"input_tokens": N}. The count is an estimate and can differ slightly from what you're billed (token counting docs).
  2. Isolate the pilot. Create a separate workspace in the Console and give it a spend limit. You can't set spend limits on the default workspace (rate limits docs).
  3. Log the usage object on every response. Record input_tokens, cache_creation_input_tokens, cache_read_input_tokens and output_tokens. Total input is the sum of the first three.
  4. Read the dashboards. The Usage page shows token charts and your cache rate. The Cost page (platform.claude.com/cost) shows spend.
  5. Project the month. Multiply the pilot's daily average by 30, then add headroom for growth.

Example forecast (illustrative numbers)

A support assistant on Sonnet 5.5 handles 20,000 requests a month, each with 1,500 input tokens and 300 output tokens:

  • Input: 30M tokens × $2 = $60
  • Output: 6M tokens × $10 = $60
  • Total: about $120/month

Now suppose 1,000 of those 1,500 input tokens are a shared system prompt served from cache:

  • Cache reads: 20M × $0.10 = $2
  • Uncached input: 10M × $2 = $20
  • Output: $60
  • Total: about $82/month, plus a small amount for cache writes

Because this is an app, the API is the only option. At $120 a month, though, a developer who also wants Max for Claude Code would have most of this bill covered by the $100 in credits.

What Are the Hidden Costs and Pitfalls of Each Option?

API costs climb with traffic, longer prompts and runaway retries. Subscription costs stay fixed, but your work can stop when a limit runs out. Settings can prevent most of these surprises.

API pitfalls and fixes

  • The tier spend cap stops everything. Monthly caps are $500 (Start), $1,000 (Build) and $200,000 (Scale). At the cap, requests return HTTP 429 with enforced_spend_limit_reached and no retry-after header, so retries, including the SDK's automatic retries, keep failing until 00:00 UTC on the 1st (rate limits docs). Fix: alert on that error code, and use Request tier increase on the Rate limits page before you need it.
  • Your own spend limit returns a different error. A limit you set returns HTTP 400 invalid_request_error ("You have reached your specified API usage limits"). Fix: handle both errors in your monitoring.
  • Credits count toward the cap. Usage paid with credits counts toward your monthly spend cap. Caps reset on the 1st, while credits refresh on your billing date. Linking a plan moves your organization to at least the Start tier, but the credits don't count toward reaching a higher tier (credits docs).
  • Auto-reload fires early. Auto-reload only watches your purchased balance, and it reloads "even if included credits remain." Fix: set a low threshold, or keep auto-reload off while you still have credits.
  • Old token counts underestimate cost. Fix: recount with the exact model ID you'll deploy.
  • Sudden traffic jumps. A sharp rise in usage can trigger acceleration limits. Fix: increase traffic gradually.

Max and Ultra pitfalls and fixes

  • An API key overrides your subscription. If ANTHROPIC_API_KEY is set, Claude Code authenticates with that key and bills you as API usage (Claude Code with Pro, Max or Ultra). If that key belongs to an organization holding only plan credits, Claude Code shows "Credit balance too low," because the credits don't cover Claude Code. Fix: unset the variable, run /login to switch to your subscription, and check /status.
  • Credits can't buy more Claude Code. API credits don't raise your limits in Claude or Claude Code. Extra usage comes from prepaid usage credits instead. Set a cap with Adjust limit rather than Set to unlimited.
  • Fable can use up half your week. Up to 50% of the weekly limit can go to Fable, and Fable uses it faster than other models. Fix: use Sonnet or Opus for routine work.
  • Ultra isn't "20x" per week. The old 20x figure described the 5-hour window. Ultra's weekly allowance is 10x Pro.
  • It doesn't scale to a team. Max and Ultra cover one person. Team plans pool credits up to $500. For example, three Standard seats plus two Premium seats get $260 a month (credits docs).

How Does Prompt Caching and Batch Processing Change the Cost Comparison?

Caching and batching lower your effective cost per million tokens. That raises the break-even volume, so the API stays cheaper than a subscription at much higher usage.

Prompt caching

Cache writes cost 1.25x base input with the 5-minute TTL, or 2x with the 1-hour TTL. Cache reads cost 0.1x base input, or 0.05x on Opus 5.5 and Sonnet 5.5 (prompt caching docs). You turn caching on per block with "cache_control": {"type": "ephemeral"}, and add "ttl": "1h" for the longer TTL.

Example (illustrative mix): a coding-agent workload on Sonnet 5.5 with 95% input and 5% output. Of the input, 85% is cache reads, 5% is 5-minute cache writes and 10% is uncached.

  • Effective input price: 0.85 × $0.10 + 0.05 × $2.50 + 0.10 × $2 = $0.41/MTok
  • Blended: 0.95 × $0.41 + 0.05 × $10 = $0.89/MTok
  • Break-even vs Max: $100 ÷ $0.89 ≈ 112M tokens/month (vs 27.8M without caching)
  • Break-even vs Ultra: ≈ 225M tokens/month

The same mix on Opus 5.5 works out to about $1.78/MTok, or roughly 56M tokens for Max.

Prompts shorter than 512 tokens on Opus 5.5, Sonnet 5.5 and Haiku 5.5 aren't cached, and you get no error. On most models, cache reads also don't count toward your input-tokens-per-minute limit (rate limits docs).

Batch processing

The Batch API halves the price. On Sonnet 5.5 at an 80/20 mix, the blended cost drops to $1.80/MTok, which moves the Max break-even to 55.6M tokens. The trade-off is that results arrive later, not in real time (batch docs). Batching suits evaluations, nightly summaries and bulk classification. It doesn't suit chat or interactive coding, which is exactly what a subscription covers.

Next steps

Measure your current usage before you switch plans.

  1. Run count_tokens on your three most common prompts with the model you actually deploy, and plug the averages into the break-even formula above.
  2. In the Console, create a dedicated workspace and give it a spend limit. Run a one-week pilot, then check the Usage and Cost pages.
  3. If you use Claude Code, run /status and check for a stray ANTHROPIC_API_KEY. If you already spend ≥$100 a month on the API, compare that bill with Max's included credits.

FAQ

Claude API vs Max plan: which is cheaper?

For your own interactive use, Max is cheaper once that usage would cost more than $100 at API rates. On Sonnet 5.5 at an 80/20 mix with no caching, that's about 28M tokens a month. With heavy caching, the threshold rises to roughly 112M. Apps can only use the API, but Max's included credits can offset that bill.

What happened to Max 20x?

It's now called Ultra. The price is still $200 a month, and existing subscribers were moved over automatically. Verified Ultra accounts have no 5-hour limit, and the weekly allowance is 10x Pro. Ultra includes $200 a month in API credits (Ultra plan article).

Is Claude Max worth it for coding?

It's worth it if you regularly hit Pro's 5-hour limit in Claude Code, or if your coding would cost more than about $100 a month at API rates. Max gives 5x Pro's usage, and the limits are shared between Claude and Claude Code. If you rarely hit Pro's limits, Pro at $20 is the better buy.

Can I use Claude Max for API access?

Not through your subscription limits. You can claim the monthly API credits, though: $100 on Max and $200 on Ultra. After 7 days on the plan, link a Console organization under Settings > Billing. The credits expire every cycle and don't cover Claude Code.

What is the cheapest way to use Claude at scale?

Use the API with the smallest model that does the job. Haiku 5.5 costs $0.10 input and $0.50 output per million tokens for prompts up to 100K tokens. Cache repeated context, and send work that isn't urgent through the Batch API at 50% off. Set workspace spend limits so a bug can't run up the bill.
