  • Gemini prices are temporary. Google's page lists Gemini 4 Argon input at "$2.00 through November 30, 2026. $4.00 starting December 1, 2026". Gemini 3.8 Flash doubles on January 1, 2027 (Gemini pricing). If you budget at today's rate, your December or January bill will be wrong.
  • Mistral publishes few per-model API prices on its main pricing page. It gives one example ("Mistral Large costs $0.5 /M tokens in and $1.5 /M tokens out") and sends you to the docs and Mistral Studio for the rest (Mistral pricing). Resellers list different numbers. OpenRouter, for example, shows Mistral Medium 3.5 at $1.65 in / $8.25 out (OpenRouter). Confirm the price in your own Mistral console before you budget.

Every Grok model doubles its rates at 200K tokens and above (xAI models). OpenAI defines long context as more than 272K input tokens, and rates there "typically double" where a long-context variant exists (OpenAI pricing).

How Has LLM API Pricing Changed from 2025 to 2026

Prices for comparable tiers fell by roughly 20–50% between late 2025 and October 2026. At the same time, a new, more expensive top tier appeared above the old flagships. That means comparing a "flagship" price from 2025 with one from 2026 often compares two different products.

Cached input got much cheaper

The bigger 2026 change was in cache pricing. Anthropic's standard cache read is 10% of base input. On Opus 5.5 and Sonnet 5.5 it is 5%, and on Fable 5.1 it is 2.5% (Claude models overview). Fable 5.1's cache hits cost $0.25/M, compared with $1/M on Fable 5, at the same base price (Claude pricing). At OpenAI, gpt-6.1-sol's cached input is $0.10, half of gpt-6-sol's $0.20 (OpenAI pricing). For agent workloads that resend the same context on every turn, this matters more than the headline price.

Context windows grew

Claude Opus 4.5 had a 200K context window and 64K max output. Every current Claude model has 1M context and 128K max output (Opus 4.5 page). OpenAI's three recommended GPT-6 models each have a 1.05M window (OpenAI models).

Common mistake: comparing tokens across generations as if they were the same unit. Anthropic says 1M tokens is about 555k words on the tokenizer introduced with Claude Opus 4.7, while earlier models fit about 750k words into 1M tokens (Claude models overview). The same text can produce more tokens on a newer model. Fix: re-count tokens on a sample of your real prompts after any model upgrade, instead of reusing old token counts.

How to Calculate Your Actual LLM API Cost (Not Just List Price)

Your monthly cost is your request volume multiplied by the per-request cost. Per-request cost is uncached input, cached input and output tokens, each multiplied by its own per-million rate.

The formula

cost_per_request = (uncached_input × input_rate
                  + cached_input × cache_read_rate
                  + cache_write_tokens × cache_write_rate
                  + output_tokens × output_rate) / 1,000,000

monthly_cost = cost_per_request × requests_per_month
batch_cost  = monthly_cost × 0.5   (if the job can wait for Batch)

Steps to build your own calculator in a spreadsheet

  1. Measure real token counts. Log 50–100 production-like requests and record the usage fields the API returns. On Claude, total input is cache_read_input_tokens + cache_creation_input_tokens + input_tokens. The input_tokens field alone only counts tokens after the last cache breakpoint (Claude rate limits).
  2. Create one row per model with columns for input rate, cache read rate, cache write rate and output rate, copied from the table above.
  3. Add columns for average uncached input, cached input and output per request, then apply the formula.
  4. Multiply by monthly requests. Add a second "after promo" column for Gemini rows, using the December 2026 and January 2027 prices.
  5. Add a 0.5 multiplier for any traffic you can move to Batch. OpenAI, Anthropic and Google all list a 50% batch discount (OpenAI Batch, Claude models, Gemini pricing).

LLM API Cost Comparison by Task Type: Chat vs Code vs Long-Context

The cheapest model changes with the task. Short chat is mostly output, coding agents resend the same context over and over, and long-document work is mostly input. Use the example shapes below, then replace them with your own token counts.

Chat (short prompts, short answers)

The $0.10 / $0.50 models win at volume, as the chatbot table above shows. Their limitation is quality on harder questions. Anthropic describes Haiku 5.5 as built "for high-volume, latency-sensitive tasks such as classification, extraction, and routing" (Claude models overview). A common setup is to send most traffic to Haiku or Luna and pass only difficult questions to a mid-tier model.

Coding agents (many turns, heavily cached context)

Long-context (one 400K-token document, 20 questions)

Example: the document is cached once, then 20 questions are asked about it, with 500 output tokens per answer.

  • Claude Haiku 5.5 (>100K tier): cache write 400K × $0.625 = $0.25, plus 7.6M cached reads × $0.05 = $0.38, plus output $0.03. Total about $0.66.
  • Gemini 3.8 Flash (promo, implicit caching): first pass 400K × $0.75 = $0.30, plus 7.6M × $0.075 = $0.57, plus output $0.04. Total about $0.91, but only if the implicit cache actually hits (Gemini caching).
  • Claude Sonnet 5.5: write $1.00, reads $0.76, output $0.10. Total about $1.86. Without caching, the same job costs about $16.
  • grok-4.3 (≥200K rates): $1.00, plus 7.6M × $0.40, plus output. Total about $4.09 (xAI models).

Pitfall: Gemini's implicit caching is automatic, but a hit isn't guaranteed. Google advises putting large repeated content early in the prompt and sending similar requests close together (Gemini caching).

Set a spend limit on Claude (exact steps)

  1. In the Claude Console, open Billing (platform.claude.com/settings/billing).
  2. In the Spend limits section, click Adjust limit (or Set limit if none exists).
  3. Enter a value below your tier's cap and save (Claude rate limits).

To raise the cap itself, open the Rate limits page (platform.claude.com/usage/limits) and use Request tier increase.

Common mistake: treating a spend-cap error like a rate-limit error. When an Anthropic organization reaches its tier cap, requests return HTTP 429 with no retry-after header until 00:00 UTC on the first of the next month, so retries, including the SDK's automatic ones, keep failing (Claude rate limits). Fix: check error.details.error_code for enforced_spend_limit_reached and alert a human instead of retrying.

How to judge value

  1. Build 50–200 test cases from real traffic, each with a pass/fail check.
  2. Run each candidate model and record its pass rate and actual token usage.
  3. Compute cost per passed task = total cost ÷ number of passes. If a model is cheaper per token but fails more often and needs retries, it can cost more per passed task.
  4. Re-run the eval when a promo ends or a new model ships.

Example (an illustration): if gpt-6.1-sol and Sonnet 5.5 both pass 92% of your tests, the tie is decided by cached-input share and output length, because their list prices are the same. Independent leaderboards such as Artificial Analysis are useful for building a shortlist. Their limitation is that they can't tell you how a model handles your specific prompts.

Who this approach is NOT for: if you spend under about $50 a month, a full eval is overkill. Pick a model from the first table, set a spend limit, and move on.

What Developers on Reddit Say About LLM API Pricing (and What's Outdated)

Reddit threads such as those on r/LocalLLaMA and r/OpenAI are useful for spotting cost traps you hadn't thought of. Treat any price quoted there as a lead to check, because model names and rates change several times a year.

How stale can a thread be? Claude Opus 4.5 was released on November 24, 2025, at $5 / $25, and less than a year later it is a legacy model, with Opus 5.5 at $4 / $20 (Opus 4.5 page). A thread from early 2026 recommending Sonnet 4.6 at $3 / $15 is now out of date on price.

When reading a thread:

  1. Check the post date against the model's release date on the vendor's model page.
  2. Look for the model ID. "Claude Sonnet" with no version number tells you nothing about price.
  3. Re-check any cost complaint against the current caching rules. Many complaints about a surprise bill come down to cache misses or long-context surcharges. Both are covered in the next section, and both are documented by the vendors.
  4. Ignore anecdotes that don't include token counts. "My bill was $400" means nothing without the volume behind it.

Third-party comparison sites have the same problem. Several pages appear in search results under this query (CloudZero, BenchLM). Use them to discover models, then confirm every number on the official page.

Hidden Costs in LLM API Pricing: Caching, Batch, and Rate-Limit Overages

The headline price leaves out cache-write charges, cache storage fees, speed-tier premiums, tool fees and long-context surcharges. Any one of these can outweigh a $1 difference in list price.

Caching costs to write, and sometimes to store

  • Anthropic: cache writes cost 1.25× base input for the default 5-minute TTL, or 2× for a 1-hour TTL ("ttl": "1h" in cache_control). Prompts below the model's minimum length can't be cached at all: 512 tokens on current 5.x models, and up to 4,096 tokens on Haiku 4.5 and Opus 4.5/4.6 (Claude prompt caching).
  • Google: Gemini 3.8 Flash charges cache storage of $0.50 per million tokens per hour until Dec 31, 2026, then $1.00 (Gemini pricing). Explicit caching "is not supported… for Gemini 4 Argon and onward", and implicit caching needs at least 4,096 tokens on Argon and 3.8 Flash (Gemini caching).
  • Mistral: cached input tokens "reduce input cost by up to 90% for repeated prompts" (Mistral pricing).

Steps to check that caching works on Claude: mark the stable part of the prompt (system prompt, tool definitions, documents) with cache_control. Then confirm that cache_read_input_tokens is greater than zero on the second request. You can also watch the cache rate on the Usage page's Rate Limit – Input Tokens chart (Claude rate limits). On most Claude models, cached reads also don't count toward your input-tokens-per-minute (ITPM) rate limit, so caching raises your effective throughput as well.

Common mistake: putting a timestamp or user ID at the top of the prompt. That changes the prefix on every request, so the cache never hits. Fix: put the content that changes after everything that stays the same.

Batch: half price, slower results

OpenAI's Batch API gives a 50% discount, returns results within 24 hours, accepts up to 50,000 requests per batch (200 MB file), and doesn't count against standard rate limits (OpenAI Batch). Anthropic and Google also take 50% off batch requests. Limitation: batch doesn't work for anything a user is waiting on.

Speed tiers and tool fees

  • OpenAI's Fast tier doubles the price: gpt-6-astra costs $20 / $100 there. The Flex tier halves it: gpt-6-luna drops to $0.05 / $0.25 (OpenAI pricing).
  • OpenAI web search costs $10 per 1,000 calls plus the search-content tokens, billed at the model's rates (OpenAI pricing). An agent that searches on every turn can spend more on search than on tokens.

Spend caps that pause production

Each tier caps monthly spend: $500 on Anthropic's Start tier and $250 on Gemini's Tier 1 (Claude rate limits, Gemini rate limits). If launch traffic pushes you past the cap, the API stops serving requests until the tier is raised. Fix: request the tier increase a week before launch, not on launch day.

Next steps

You can have a realistic monthly estimate today with the three steps below.

Do it yourself today:

  1. Log 50 real requests and record their input, cached-input and output token counts.
  2. Put two or three candidate models into the spreadsheet formula above. Add the post-promo Gemini prices if Gemini is on your list.
  3. Set a spend limit below your tier cap on every provider you use. On Claude, that's Billing → Spend limits → Adjust limit.

If you'd rather not manage API billing yourself: for an individual or a small team using Claude mainly for interactive coding and writing, a flat subscription may be simpler. Claude Pro costs $20/month ($17/month billed annually), and Max starts at $100/month for 5× or 20× Pro's usage (claude.com/pricing; as of October 2026, check the official page). These plans suit people who want a predictable bill and don't need to build an app. They don't fit products that serve your own customers, because subscriptions don't replace API access for your app's traffic. They also have usage limits rather than unlimited use. For a free way to try models, Google's free tier for Gemini 3.8 Flash costs nothing, but you'll need to move to a paid tier for higher limits and for models such as Gemini 4 Argon, which has no free tier (Gemini pricing).

FAQ

What's the best way to compare LLM API pricing?

Compare cost per task, not price per token. Measure the input, cached-input and output tokens of real requests, apply each model's three rates, then multiply by your monthly volume. Use each vendor's official pricing page as the source, because third-party tables often lag behind price changes.

What does an LLM models API pricing comparison look like in October 2026?

Listed prices fall into four clear tiers: $10 / $50 (GPT-6 Astra, Claude Fable 5.1), $4 / $20 (Claude Opus 5.5), $2 / $10 (GPT-6.1 Sol, Claude Sonnet 5.5, Gemini 4 Argon's promo rate) and $0.10 / $0.50 (GPT-6 Luna, Claude Haiku 5.5). xAI's Grok 4.7 is $2 / $6 under 200K tokens. Gemini's current rates double on December 1, 2026 (Argon) and January 1, 2027 (3.8 Flash).

Which AI LLM API is cheapest overall?

Among current models from the five providers, Gemini 2.5 Flash-Lite ($0.10 / $0.40) has the lowest list output price. GPT-6 Luna and Claude Haiku 5.5 follow at $0.10 / $0.50. Using OpenAI's Flex tier halves Luna's price to $0.05 / $0.25 if you can accept slower processing. The cheapest model is only a bargain if it passes your quality checks.

Why do output tokens cost more than input tokens?

Every provider here prices output at roughly 3–5× input, for example $2 in and $10 out on Sonnet 5.5 and GPT-6.1 Sol. For chat and coding, that means output length often drives the bill. Limiting max_tokens and asking for concise answers cuts cost directly. For long-document work, input and cache rates matter more.
