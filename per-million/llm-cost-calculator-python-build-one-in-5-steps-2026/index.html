It reads token counts from each API's own usage fields, so your estimates come from the same numbers the provider bills on. Copy it, change the model list to the ones you use, and check the prices against the official pages before you trust any total.

What Is an LLM Cost Calculator and Why Build Your Own?

An LLM cost calculator multiplies token counts by per-model prices to estimate what you will spend on the API. If you build your own, the prices stay current and the usage numbers are yours instead of a template's.

Web calculators help with a first guess. They tend to fail in three ways, though. Some are missing new models, such as Claude Opus 5.5 (released with retirement "not sooner than September 22, 2027" per Anthropic's models overview). Many have no fields for cached input or batch pricing. And most can't see your real input/output ratio, which drives the bill more than anything else.

A script of about 100 lines fixes all three. It runs where your API calls already happen, so it can read the exact token counts that come back in each response. It also lets you plan for a known price change. Google's pricing page says Gemini 3.8 Flash costs $0.75 input and $3.75 output through December 31, 2026, then $1.50 and $7.50 from January 1, 2027 (Gemini API pricing). A generic calculator won't warn you that your Flash bill doubles in ten weeks. Your own price table can hold both rates with a switch-over date.

Pitfalls to avoid when you build one:

  • Hardcoding one price per model. You need input, cached input, output and sometimes a long-context tier.
  • Estimating output length once and never checking it. Log the real output_tokens value, because reasoning models add hidden thinking tokens.
  • No "checked on" date. Put a PRICES_CHECKED constant at the top of the file so stale prices are easy to spot.

If you only use OpenAI, the shorter formula in OpenAI API Pricing Calculator: 2026 Formula + Cost Table may be enough.

How to Count Tokens in Python for Cost Estimation

Use tiktoken for OpenAI models, the free count_tokens endpoints for Claude and Gemini, and the API response's usage fields for billing-grade numbers. The "4 characters ≈ 1 token" rule works for rough planning.

Each provider has its own tokenizer, so the same paragraph produces a different count on each. Here are your options:

Step 1: Install the libraries

pip install tiktoken openai anthropic google-genai

Step 2: Count OpenAI tokens offline

import tiktoken

def count_openai(text: str, model: str = "gpt-4o") -> int:
    try:
        enc = tiktoken.encoding_for_model(model)
    except KeyError:
        enc = tiktoken.get_encoding("o200k_base")  # fallback for newer model names
    return len(enc.encode(text))

The tiktoken README shows both tiktoken.encoding_for_model("gpt-4o") and tiktoken.get_encoding("o200k_base") (tiktoken on GitHub). The KeyError fallback matters because a tiktoken release may not know a model ID that came out after it. This count covers the text only. Chat formatting and tool definitions add a few tokens on top, which is why the logged usage numbers are the ones to trust.

Step 3: Count Claude tokens with the API

import anthropic
client = anthropic.Anthropic()

resp = client.messages.count_tokens(
    model="claude-sonnet-5-5",
    system="You are a support agent.",
    messages=[{"role": "user", "content": "Where is my order?"}],
)
print(resp.input_tokens)

Anthropic says token counting is "free to use" but has per-minute limits: 5,000 RPM on the Start tier, 10,000 on Build and 20,000 on Scale. The result is labeled an estimate (Anthropic token counting).

The same page has a warning that matters for cost: Claude Opus 4.7 and later models use a newer tokenizer that produces "approximately 30 percent more tokens" for the same text. Anthropic tells you to recount prompts against the model you plan to use (same source). So don't reuse token counts from Claude Sonnet 4.6 when you budget for Sonnet 5.5.

Step 4: Count Gemini tokens

from google import genai
client = genai.Client()
r = client.models.count_tokens(model="gemini-3.8-flash", contents="Where is my order?")
print(r.total_tokens)

Google's docs give the rule of thumb that "a token is equivalent to about 4 characters" and that 100 tokens is about 60-80 English words. They also list fixed costs for media: an image up to 384 pixels is 258 tokens, video is about 100 tokens per second and audio about 32 tokens per second (Gemini token docs).

Step 5: A no-API fallback

def rough_tokens(text: str) -> int:
    return max(1, len(text) // 4)

This fallback is fine for comparing models before you write any integration code. Don't use it for invoices. It undercounts code, non-English text and, on Claude 4.7+ models, ordinary English prose.

How to Build a Python Price Table for OpenAI, Anthropic, and Gemini Models

Keep input, cached-input and output prices per million tokens in one dictionary keyed by the exact API model ID, and add a dated comment showing when you last checked them. The table below matches the official pages as of October 2026.

Save this as llm_cost.py:

Why it's built this way:

  • Exact API IDs as keys. claude-sonnet-5-5 is the ID Anthropic lists for the Claude API, Google Cloud and Microsoft Foundry (models overview). If you call Claude through another platform such as Amazon Bedrock, check the model ID that platform returns and map it to these keys before you look up the price.
  • A long sub-dictionary for tiered models. Haiku 5.5 changes price above 100K tokens (claude.com/pricing), and Gemini Pro models change above 200K (Gemini pricing).
  • A dated future price. from_2027_01_01 records Google's announced Gemini 3.8 Flash increase so your forecast for January is correct.
  • cache_write only for Claude. Anthropic bills writes to the 5-minute cache at 1.25× the base input price. The pricing table shows Fable 5.1 at $10 base and $12.50 for a 5m write, and a 1-hour write costs $20 (Anthropic pricing docs). If you use the 1-hour cache, add another key for it.
  • Missing cache prices fall back to the input price. The Gemini page shown here gives no cache rate for 2.5 Flash-Lite, so the calculator falls back to the full input price.

Prices are stored as plain floats so they're easy to read. The cost function converts them to Decimal before doing any arithmetic.

How to Calculate Cost Per API Call in Python

Write one function that takes the model name and the token counts, picks the right price tier, applies any batch discount and returns a rounded dollar amount. Then add three small adapters, one per provider, because each SDK reports usage differently.

The core function

Add this to llm_cost.py:

from datetime import date

MILLION = Decimal(1_000_000)

def _rates(model: str, prompt_tokens: int, on: date | None = None) -> dict:
    if model not in PRICES:
        raise KeyError(f"No price for {model!r}. Add it to PRICES (checked {PRICES_CHECKED}).")
    p = dict(PRICES[model])
    if on and on >= date(2027, 1, 1) and "from_2027_01_01" in p:
        p.update(p["from_2027_01_01"])
    if "long" in p and prompt_tokens > p["long"]["above"]:
        p.update(p["long"])
    return p

def call_cost(model, uncached_in=0, cached_in=0, cache_write=0, output=0,
              batch=False, on=None) -> Decimal:
    p = _rates(model, uncached_in + cached_in + cache_write, on)
    d = lambda k: Decimal(str(p.get(k, p["in"])))
    total = (uncached_in * d("in") + cached_in * d("cached")
             + cache_write * d("cache_write") + output * d("out")) / MILLION
    if batch:
        total *= Decimal("0.5")
    return total.quantize(Decimal("0.000001"), rounding=ROUND_HALF_UP)

Decimal avoids float noise such as 0.30000000000000004 building up over a million logged rows. The batch=True flag applies the 50% Batch discount, which all three vendors list: OpenAI (pricing), Anthropic (claude.com/pricing) and Google (Gemini pricing). OpenAI's page also says the Flex tier matches Batch rates for most models, so use batch=True for Flex calls too. Batch rules differ by provider in other ways, which are covered in Batch API Discount 2026: OpenAI vs Claude vs Gemini.

Provider adapters

The three SDKs don't define "input tokens" the same way, and the adapters fix that:

def cost_openai(model, usage, batch=False):
    # usage from the Responses API; cached tokens are part of input_tokens
    cached = getattr(getattr(usage, "input_tokens_details", None), "cached_tokens", 0) or 0
    return call_cost(model, uncached_in=usage.input_tokens - cached,
                     cached_in=cached, output=usage.output_tokens, batch=batch)

def cost_anthropic(model, usage, batch=False):
    # input_tokens excludes cache reads and cache writes
    return call_cost(model,
        uncached_in=usage.input_tokens,
        cached_in=getattr(usage, "cache_read_input_tokens", 0) or 0,
        cache_write=getattr(usage, "cache_creation_input_tokens", 0) or 0,
        output=usage.output_tokens, batch=batch)

def cost_gemini(model, um, batch=False):
    # usage_metadata; thinking tokens are billed at the output rate
    cached = um.cached_content_token_count or 0
    out = (um.candidates_token_count or 0) + (um.thoughts_token_count or 0)
    return call_cost(model, uncached_in=um.prompt_token_count - cached,
                     cached_in=cached, output=out, batch=batch)

The field meanings come from each vendor's caching docs. OpenAI reports cached_tokens as a subset of input tokens (OpenAI prompt caching). Anthropic reports cache reads and writes in separate fields from input_tokens (Anthropic prompt caching). Google's price table is headed "Output price (including thinking tokens)" (Gemini pricing). Field names can change between SDK versions, so print one raw usage object before you rely on an adapter.

Quick check (example values)

print(call_cost("gpt-5-mini", uncached_in=1_000, output=300))      # 0.000850
print(call_cost("claude-haiku-5-5", uncached_in=150_000, output=500))  # long tier applies
print(call_cost("gemini-3.8-flash", uncached_in=1_000, output=300,
                on=date(2027, 1, 15)))                                 # 2027 rate

The first line works out as 1,000 × $0.25/1M + 300 × $2.00/1M = $0.00025 + $0.0006 = $0.00085.

How to Track Monthly LLM Spend Across Multiple Models

Log each call's model, token counts and cost to SQLite with a timestamp. Then group by month to see what you've spent so far and project the full bill. That is enough to catch runaway usage within a day instead of at invoice time.

Steps

  1. Create the log table once:
import sqlite3, datetime as dt

db = sqlite3.connect("llm_costs.db")
db.execute("""CREATE TABLE IF NOT EXISTS calls(
    ts TEXT, model TEXT, feature TEXT,
    uncached_in INT, cached_in INT, cache_write INT, output INT,
    batch INT, cost TEXT)""")
  1. Write one row after every API call:
def log_call(model, feature, cost, uncached_in=0, cached_in=0,
             cache_write=0, output=0, batch=False):
    db.execute("INSERT INTO calls VALUES (?,?,?,?,?,?,?,?,?)",
        (dt.datetime.now(dt.timezone.utc).isoformat(), model, feature,
         uncached_in, cached_in, cache_write, output, int(batch), str(cost)))
    db.commit()

The feature column (for example "chat", "summarize", "classify") shows which product feature is spending the money. Model-level totals can't tell you that.

  1. Get the month-to-date total and a straight-line projection:
import calendar

def month_report(month: str | None = None):
    today = dt.date.today()
    month = month or today.strftime("%Y-%m")
    rows = db.execute("""SELECT model, feature, SUM(CAST(cost AS REAL))
                         FROM calls WHERE substr(ts,1,7)=?
                         GROUP BY model, feature ORDER BY 3 DESC""", (month,)).fetchall()
    spent = sum(r[2] for r in rows)
    days = calendar.monthrange(today.year, today.month)[1]
    projected = spent / today.day * days if month == today.strftime("%Y-%m") else spent
    for m, f, c in rows:
        print(f"{m:24} {f:12} ${c:,.2f}")
    print(f"Spent: ${spent:,.2f}  Projected month: ${projected:,.2f}")
  1. Add a guard. For example, if projected goes over your monthly budget, raise an exception in a scheduled job or send the result to whatever alerting you already run. The calculator only reports numbers; deciding what happens when a limit is hit is up to your code.

Pitfalls

  • Timezones. Store UTC. Otherwise late-night calls fall into the wrong day or month.
  • Retries. If your HTTP client retries after a timeout, log each attempt that returns usage, and compare your log with the provider's billing console to see whether timed-out attempts show up as billed usage.
  • Streaming. Log usage after the stream finishes, not on the first token, and check your SDK's streaming docs for which event or chunk carries the usage data.
  • Server tools. Anthropic's count endpoint rejects requests with server tools such as web search, and the real usage appears in the Messages API usage object (Anthropic token counting). Tool fees billed per call may also need their own column.
  • Gemini context caching. Google bills cached tokens at the rates in the table, and the Gemini pricing page lists separate charges for cache storage. If you use explicit caching, add those charges to the log as their own line.

Check the logged total against the vendor's billing console once a month. If the two differ by more than a few percent, look first for a price change or a model alias you haven't added to the table.

How to decide:

  2. Run them through two or three candidate models and record usage with the adapters above.
  3. Score the answers against your own pass/fail check.
  4. Divide the total cost by the number of passing answers. The lowest cost per passing answer wins.

A cheap model that fails 30% of the time and needs a retry on a pricier model can cost more than going to the pricier model first. Common Pitfalls When Estimating LLM Costs

Most calculators drift from the real bill for a few reasons: output is underestimated, cache and batch rates are ignored, and the price table gets old. Each one has a simple fix.

MistakeWhat happensFix
Guessing output lengthOutput costs 4-8× input, so a 2× miss on output can double the billLog real output_tokens and use the 90th percentile in forecasts

Double-counting cached tokens on OpenAICached tokens are already inside input_tokensSubtract cached_tokens before pricing uncached input

FAQ

How much does an LLM cost?

LLM APIs bill per million tokens, with output priced higher than input. As of October 2026, gpt-5-nano costs $0.05 input and $0.40 output per million tokens. claude-fable-5-1 costs $10 input and $50 output. A typical small app on a mini-tier model can run under $100 a month, but your token volume decides the total.

How do I count tokens in Python?

For OpenAI models, use tiktoken.encoding_for_model() locally. For Claude, call client.messages.count_tokens(), which is free but rate-limited. For Gemini, use client.models.count_tokens(). For billing-grade numbers, read the usage fields that come back with every response.

How do I calculate API cost per call?

Multiply uncached input, cached input and output tokens by their per-million rates, add them up and divide by 1,000,000. Apply 0.5 if the call went through a Batch API. The call_cost() function above does this with Decimal and handles the long-context tiers.

Is GPT-4o cheaper than Claude or Gemini?

Not at the list prices on the official pages as of October 2026. gpt-4o costs $2.50 input and $10 output per million tokens. claude-sonnet-5-5 costs $2 and $10, and gemini-3.8-flash costs $0.75 and $3.75 through December 2026. For simple tasks, gpt-4o-mini, gemini-2.5-flash-lite and claude-haiku-5-5 all cost far less.
